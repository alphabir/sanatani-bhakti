# Sanatani Bhakti — Fix & Release Plan

_Written 2026-09-05 against commit `8d5cde3` (the only commit). Everything marked **verified** was confirmed by reading code, running `tsc`, or querying the live InsForge project `jyotish-ai` — not inferred._

## 0. Where the app actually stands

Expo SDK 56 / RN 0.85 / TypeScript, ~8,700 LOC, **bare workflow** (`android/` is committed — 59 files). Backend is **InsForge** (`c95v9mim.ap-southeast`). **Firebase is not vestigial:** the committed `android/` boots into a **native Kotlin Firebase login screen** — `.AuthActivity` holds the `MAIN`/`LAUNCHER` intent-filter (`AndroidManifest.xml:29-38`; `.MainActivity` at :39 has none), with `firebase-bom:33.10.0` + `firebase-auth` and the `google-services` plugin in `android/app/build.gradle:188-201`. React Native never reads it, so anyone who signs in there gets a dead identity, and its Google button is registered to the debug keystore so it fails on any real build. **Two auth systems, neither finished.** The repo was very likely generated by an AI IDE.

`npx tsc --noEmit` passes clean. There are **no tests of any kind**. The only automated gate is the type-checker, so every date string, id, and sort order below has to be reasoned about by hand.

**Four things are actively wrong right now:**

| | What | Blast radius |
|---|---|---|
| 🔴 | `bhakti_user_stats` is **world-writable** (`allow_anon_all`: ALL / anon / `true` / `true`) and the anon key is in a public repo | Anyone can read, edit, or **delete** every user's stats |
| 🔴 | `elevenlabs-tts` runs with **no Authorization header at all** — verified live | Anyone with the URL (it's in the APK) spends your ElevenLabs balance |
| 🟠 | Every user sees **the wrong Rahu Kaal, every day** — Monday-first array indexed by Sunday-zero `getDay()` | The one *avoid* window in the app is off by a day |
| 🔴 | The APK boots into a **native Firebase login** React Native ignores; the InsForge login buried in Profile **loses its session on every restart** (SDK token is in-memory; the app writes `AUTH_TOKEN` and never reads it) | Every user, every launch |

## 2. Decisions already made

- **Auth: InsForge only — and delete the Kotlin Firebase gate.** `signInWithIdToken` supports **Google only**, so Firebase tokens can't become InsForge sessions; keeping both means two identity systems forever. Google sign-in on the phone uses **`signInWithIdToken` + `@react-native-google-signin/google-signin`** — *not* `signInWithOAuth`, whose PKCE flow needs `crypto.subtle`, which Hermes doesn't have (SDK `index.js:957-966` throws). Google is already enabled on the InsForge backend.
- **Guest identity, flagged.** InsForge has no anonymous auth and no account linking. On first launch — *after* first paint, never blocking it — synthesize `guest-{uuid}@…` + random password → `signUp` → **SecureStore** (new dep `expo-secure-store`), and create the user's `bhakti_user_stats` row with **`is_guest = true`**. The flag is what lets the server give guests different rules (TTS quota, daily reward) and purge stale guests. Guest → Google/email creates a new uid; a small edge function **merges** (max punya/jaap/streak, union favorites), flips `is_guest = false`, stamps `upgraded_at`. Sessions for **all** account types are persisted in SecureStore and restored at boot — today none are.
- **Free tier, enforced server-side by the flag:** guests get 3 HD recitations *total*, signed-in users N/day, VIP unlimited; voice and model hard-coded server-side, text whitelisted to known mantras; ~5 new guests per IP per day so minting guests can't multiply quota. Cached playback free for everyone, forever.
- **Aaj ka Prasad — the daily reward, tiered by the flag.** Tap-to-claim card at the top of Home. Guest **+5**; signed-in **+15**, **+30 from day 7** (2×, signed-in only). Claim today only (India time); streak = consecutive claimed days, server-computed, replaces the phone's clock-cheatable streak. A guest on day 6 sees *"Sign in to unlock 2× tomorrow"* — the best conversion moment in the app. Every card state comes from the server response.
- **Festival schema (locked):** `date: string` → **`dates: Record<number, string>`** keyed by year; `regions?` sparse and optional. 63 dates verified by 3 independent researchers + reconciliation (2026-09-14 → 2027-12-13; 1 disputed: Durga Ashtami 2026, 18 vs 19 Oct — show both).
- **Region:** "Apna Panchang" — persist the **state code**, derive the region at read time (splitting a region later = two-line edit, no migration).
- **Payments: two sealed lanes.** The five existing SKUs are all digital goods and **stay on Google Play Billing** — India's User Choice Billing is legal but nets under ₹1–₹2 per transaction after Razorpay's fee, makes you seller of record with 24-hour reporting, and needs Play Billing Library APIs `expo-iap` almost certainly doesn't expose. The "in-app payment gateway" is **Razorpay/UPI for a new physical-seva catalogue** (puja booked at a real temple, chadhava, prasad delivery) — Play policy says Play Billing *must not* be used for physical goods/services, so no enrollment, no reporting, no Google fee. The two lanes never share a screen, button, or price list. Both write to the one existing ledger (`wallet_transactions` already CHECKs `GOOGLE_PLAY` / `UPI_RAZORPAY`); entitlements become server-derived.

## 4. Build & release procedure

```bash
npx eas-cli@latest login                                  # interactive, your Expo account
npx eas-cli@latest build --profile preview --platform android   # installable APK, cloud build
```

- `preview` → `buildType: "apk"`, `distribution: internal`. `production` → app-bundle, `autoIncrement: true`, `appVersionSource: remote` (EAS owns `versionCode`).
- First run prompts to create the EAS project and write `extra.eas.projectId` — commit that.
- EAS generates and stores the keystore on first build. **Keep it.** A different keystore later = Play rejects the upload.
- **Bare workflow rule:** any `app.json` plugin change (AdMob ID, `compileSdkVersion`, permissions strings) needs `npx expo prebuild --clean` to reach `android/`. New JS-only deps autolink and do not.
- Ads and IAP are native → dead in Expo Go → **verify on a device from a preview build, never on web.**
- Local build is possible (`android/gradlew` is committed) but needs JDK 17 + Android SDK (~10 GB); neither is installed.

**Blocker today:** no Expo login on this machine. Either log in interactively, or create an access token at expo.dev → Account Settings → Access Tokens and set `EXPO_TOKEN`; first-time project creation may still need one interactive run.
